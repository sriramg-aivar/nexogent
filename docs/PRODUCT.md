# Nexogent — Product Overview

## What it is
Nexogent is an **AWS SecOps agent that you deploy into a client's own AWS account**.
Once installed, it runs 24/7 inside the client's Amazon EKS cluster, continuously
giving the client a clear picture of their cloud security posture.

It is a **per-client product, not a SaaS**. Each client gets their own private
deployment inside their own account. Their data never leaves their account.

## What it does
1. **Discovers every AWS resource** in the account and groups them by service
   (EC2, S3, IAM, Lambda, RDS, DynamoDB, ECS, EKS, …).
2. **Runs read-only security checks** — its own built-in checks plus the open-source
   **Prowler** scanner (hundreds of checks mapped to CIS / AWS FSBP).
3. **Ranks every finding by real risk**, not just raw severity, using a scoring
   rubric (severity + exposure + reachability + resource criticality).
4. **Explains each finding in plain English** with concrete remediation steps,
   generated by **Amazon Bedrock** (with an offline fallback so it always works).
5. **Presents everything in a dashboard** where the client picks a service or a
   resource and sees: what exists, what's misconfigured, what threats are present,
   and whether everything is fine.

## What it does NOT do
- It is **read-only and recommend-only**. It never changes, deletes, restarts, or
  remediates anything in the account. Every output is a recommendation a human reviews.
- It is not a shared multi-tenant service. One deployment = one client account.
- It does not retain access after handover. The client holds full admin.

## Who it's for
Companies that want continuous, automated security coverage of their AWS account
without building a security team or standing up a heavy enterprise platform. They
hand us scoped deploy access, we install Nexogent into their account, and from then
on their dashboard shows their live posture.

## How a client engagement works
1. We share **PREREQUISITES.md** — the exact AWS access and resources needed.
2. The client provisions that access (temporary deploy credentials / role).
3. We deploy Nexogent into their EKS cluster via the Helm chart.
4. The agent runs; the client uses the dashboard.
5. We hand over. The account and its admin remain entirely the client's.

## Technology
- **Pure Go** agent — a single small static binary, ideal for running inside a
  client's cluster with no interpreter or dependency sprawl.
- **Amazon Bedrock** (Claude) for the AI explanation/report layer — a hosted API,
  so there is no local ML model to train or run.
- **Prowler** (open source) for broad, maintained check coverage.
- **React** dashboard.
- **Helm** for repeatable per-client deployment onto Amazon EKS.

## Why Go (and no Python)
A security product that lives inside someone else's account should be small,
auditable, and dependency-light. Go compiles to one static binary in a tiny
container. The "intelligence" is Amazon Bedrock, which Go calls directly over the
AWS SDK — so there is no need for a Python ML runtime anywhere in the product.

## Positioning (honest)
Nexogent does **not** reinvent vulnerability detection. Detection is delegated to
native read-only AWS APIs and the open-source Prowler. Nexogent's value is the
layer on top: **resource inventory grouped by service, risk ranking, plain-English
explanations, a clean dashboard, and one-command per-client deployment** — delivered
safely as read-only, inside the client's own account.
